# P4 reconstruction audit

## Scope

This audit tests the current reconstruction pipeline and the evaluator's failure
handling. It uses all 21 Middlebury 2006 ThirdSize scenes from view 5, with one
fixed 160 × 160 center crop per scene. Earlier fusion calibration used view 1
crops, so the audit changes the camera view while retaining the same scene
collection. The target is disparity in third-size pixels. These results do not
measure metric depth from a physical LR sensor. [Middlebury 2006 dataset](https://vision.middlebury.edu/stereo/data/scenes2006/)

Every method receives the same RGB, LR disparity, and validity mask for each
scene, scale, and condition. The input is generated by antialiased bicubic
downsampling. The four conditions are clean, 1% relative Gaussian noise, 25%
random dropouts plus two square block holes, and both corruptions together.
The block side is 15% of the LR image dimension. Existing ground-truth holes
are excluded from scoring, and a six-pixel HR border is cropped. PSNR and SSIM
use a fixed range of 85 disparity pixels.

## Reproduce

Use the official third-size two-view archive and extract it into a directory
containing the scene folders directly. Place the official ×4 and ×8 SGNet
`_R.pth` weights under `checkpoints/sgnet`. The exact model SHA-256 hashes are
recorded in [summary.json](summary.json). The dataset archive used for this run
had SHA-256 `d09a8f6a63cd85a0baf7df48353087f447d3b1a4b40824d95cbd043ac555e665`.
The audit used the default application fusion settings. [Dataset archive](https://vision.middlebury.edu/stereo/data/scenes2006/ThirdSize/zip-2views/ALL-2views.zip) · [SGNet model source](https://github.com/yanzq95/SGNet#models)

```powershell
$env:OMP_NUM_THREADS = "2"
$env:MKL_NUM_THREADS = "2"
.\.venv\Scripts\python.exe -m pytest -q -p no:faulthandler
.\.venv\Scripts\python.exe -m scripts.eval_submission_audit --root tmp/classical-middlebury
```

Machine used for this run was Windows with Python 3.12.10, PyTorch 2.11.0+cu128,
and a 4 GiB NVIDIA GeForce RTX 2050. The audit sets OpenCV and PyTorch CPU
thread counts to two. Latency includes reconstruction and CUDA synchronization,
and excludes loading the dataset and scoring. A condition's GPU peak covers all
its methods and can include cached models. It is PyTorch allocated memory,
which differs from total device usage and host RAM.

## Automated checks

The full suite passed **137 tests** with two deprecation warnings from
`pytest-flask`. Coverage includes mask handling, invalid and constant inputs,
block-hole filling, RGB texture rejection, the resize operator, checkpoint
loading, CUDA inference, CLI exports, and UI diagnostics with and without
ground truth.

A new regression test forces SGNet to fail on the first of two samples while a
checkpoint is discoverable. The evaluator records one hybrid failure and one
later success. The failed sample generates no hybrid metrics row. The app
continues to show a labeled classical fallback when SGNet fails.

### Application and repeatability checks

I called the Gradio processing entry point on the combined-corruption
`Aloe_view5` crop at ×2, ×4, and ×8, once with ground truth and once without.
All six runs returned positive, finite 160 × 160 float32 depth. The NPY export
matched the in-memory output exactly. Measurement diagnostics and comparison
images were present in all six runs. Reference metrics and the error map
appeared only when ground truth was supplied. ×2 reported classical fallback
and ×4 and ×8 reported hybrid.

The two outputs matched bit-for-bit at ×2 and ×4. The first ×8 pair differed
by up to 0.00226 disparity pixels. I then ran five more ×8 reconstructions
in one process with and without ground truth. Relative to the
first run, the largest absolute difference was 0.03745 pixels in SGNet and
0.00375 in the hybrid output. The largest hybrid RMS difference between
those outputs was 0.00017 pixels. The classical branch was bit-identical.
The difference also occurred between two runs without ground truth, so it
does not require the reference-metrics path. The specific SGNet operation
responsible was not isolated.

At four decimal places, the ×8 noise means are 0.8706 for classical and
0.8715 for hybrid.
Classical had lower mean RMSE than all interpolation baselines in every
condition. Hybrid cut SGNet's mean RMSE by **60% at both ×4 and ×8** with noise
and holes. Classical alone was about 4% better than hybrid in those same
conditions. On clean inputs, hybrid had the lowest mean RMSE, while SGNet had
slightly better Edge F1 at both scales. With noise and holes, classical Edge F1
was 0.863 at ×4 and 0.803 at ×8, versus 0.848 and 0.792 for hybrid.

The clean ×4 hybrid advantage over SGNet was 0.004 disparity pixels, with a
paired 95% bootstrap interval of −0.011 to +0.001 for hybrid minus SGNet.
With noise and holes, the hybrid minus classical interval was +0.019 to
+0.037 at ×4 and +0.020 to +0.053 at ×8. These are exploratory percentile
intervals from 10,000 resamples of the 21 paired scenes with seed 2026. They
are unadjusted for multiple comparisons.

full-resolution, browser, or hosted latency.

## Failure case and limits

The hardest hybrid sample by RMSE was `Aloe_view5` with noise and holes at
×8. Hybrid scored 3.140 disparity pixels, classical 3.117, and SGNet 5.659.
Hybrid reduced the deep branch's error substantially, but retained a small
penalty over classical. Across all 21 ×4 combined-corruption scenes, none
had lower hybrid RMSE than classical. These results support a separate
classical-only comparison in future evaluations of sparse inputs.

The crop audit does not cover ×16, physical sensor noise, new scene collections,
or hosted deployment. The alternate camera views still depict the scenes used
in earlier work, and the corruption patterns use one deterministic seed per
scene. Use [per_image.csv](per_image.csv) for paired analysis and
[summary.json](summary.json) for the complete metrics, timings, failure counts,
and checkpoint fingerprints.
